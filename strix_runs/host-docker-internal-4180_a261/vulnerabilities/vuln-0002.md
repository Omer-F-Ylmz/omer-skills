# Missing Security Headers on Static File Server

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-10-28 07:14:13 UTC
**Target:** http://host.docker.internal:4180
**CWE:** CWE-693
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Low

## Description

The Python `http.server` does not set any security headers, leaving the application exposed to various client-side attacks and information disclosure.

## Evidence

HTTP responses lack: Content-Security-Policy, Strict-Transport-Security, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy. Server header discloses: `Server: SimpleHTTP/0.6 Python/3.12.10`.

## Impact

Absence of security headers increases risk of clickjacking (no X-Frame-Options), MIME type sniffing attacks (no X-Content-Type-Options), reduces defense-in-depth against XSS (no CSP), and leaks server technology stack (Server header). The Server header reveals Python 3.12.10 which could aid version-specific attacks.

## Counterevidence

This is a demo application served by Python's development server (http.server). In a production deployment, this would typically run behind a reverse proxy or CDN that adds security headers. The development server is not intended for production use.

## What Would Change This Severity

If deployed behind a CDN/WAF that adds security headers, or if this is purely a local development server, severity would be Informational. In production without mitigating infrastructure, severity remains Low to Medium depending on sensitivity.

## Technical Analysis

Python's `http.server` is a development-only server that does not implement any security headers by default. It exposes the Python version and server type via the `Server` header. In production environments, this information disclosure and lack of security headers would be considered a misconfiguration. The headers missing are standard defense-in-depth measures: CSP prevents XSS, X-Frame-Options prevents clickjacking, X-Content-Type-Options prevents MIME sniffing, HSTS enforces HTTPS, Referrer-Policy controls referrer leakage, and Permissions-Policy controls browser feature access.

## Proof of Concept

1. Send a HEAD request to http://host.docker.internal:4180/
2. Observe missing security headers in response
3. Note Server header discloses Python version

```python
curl -I http://host.docker.internal:4180/
```

## Remediation

Implement security headers by: (1) Subclassing `SimpleHTTPRequestHandler` and overriding `end_headers` to add security headers, (2) Deploying behind a reverse proxy (nginx, Apache, Cloudflare) that adds security headers, or (3) Using a production web server instead of Python's development server. Minimum recommended headers: Content-Security-Policy, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin.

## Assumptions

The application may be deployed to production where security headers are expected.
