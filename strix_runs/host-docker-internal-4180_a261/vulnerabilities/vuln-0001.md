# Directory Listings Enabled on Static File Server

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2026-10-28 07:11:46 UTC
**Target:** http://host.docker.internal:4180
**CWE:** CWE-548
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Low

## Description

Python's built-in `http.server` has directory listing enabled on multiple paths (`/vendor/`, `/vendor/three/`, `/vendor/gsap/`, `/vendor/lenis/`, `/js/`, `/docs/`), exposing the full file tree structure and exact library versions to unauthenticated remote attackers.

## Evidence

Directory listings accessible at /vendor/, /vendor/three/, /vendor/gsap/, /vendor/lenis/, /js/, /docs/ returning HTML index pages with file names, sizes, and modification times.

## Impact

Attackers can enumerate all static assets, discover library versions (Three.js r170, GSAP 3.12.5, Lenis), and map the complete application structure. This facilitates targeted attacks against known vulnerabilities in specific library versions and provides reconnaissance for further attacks.

## Counterevidence

This is a demo/portfolio application served by Python's http.server where directory listing may be intentional for demonstration purposes. However, as a security assessment, this is a misconfiguration that would be flagged in any production deployment. No WAF, access controls, or authentication protect these listings.

## What Would Change This Severity

If this is confirmed as an intentional demo feature with no production deployment, severity would lower to Low/Informational. If deployed to production with sensitive assets in the served directory, severity would increase to High.

## Technical Analysis

The Python `http.server` module (SimpleHTTP/0.6) serves static files from its working directory with directory indexing enabled by default. When a request is made to a directory path without an index file (or when the directory itself is requested), the server returns an HTML directory listing showing all files and subdirectories. This is a default behavior of Python's `http.server` and is not appropriate for production deployments. The affected paths include `/vendor/`, `/vendor/three/`, `/vendor/gsap/`, `/vendor/lenis/`, `/js/`, and `/docs/`.

## Proof of Concept

1. Navigate to http://host.docker.internal:4180/vendor/
2. Observe the directory listing showing all vendor libraries and their versions
3. Navigate to /vendor/three/, /vendor/gsap/, /vendor/lenis/, /js/, /docs/ to see complete file trees

```python
curl http://host.docker.internal:4180/vendor/
curl http://host.docker.internal:4180/js/
curl http://host.docker.internal:4180/docs/
```

## Remediation

Disable directory listing by either: (1) Adding an index.html file to each directory, (2) Running the server with a custom handler that overrides `list_directory` to return 403/404, or (3) Using a production web server (nginx, Apache) with directory indexing disabled. For Python http.server, subclass `SimpleHTTPRequestHandler` and override `list_directory` to return an error response.

## Assumptions

The application is deployed using Python's built-in http.server in a production or staging context where directory listing is undesirable.
