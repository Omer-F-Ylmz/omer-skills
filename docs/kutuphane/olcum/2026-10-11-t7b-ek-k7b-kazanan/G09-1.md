## Bulgular (en ciddiden aza)

**1. Kritik: SQL Injection** (`db.query(... + req.query.id)`)
`id` sorguya doğrudan ekleniyor, böylece saldırgan sorgunun kendisini yazabiliyor.
- `?id=1 OR 1=1` → tablodaki tüm satırlar döner.
- `?id=0 UNION SELECT ...` → başka tablolardan veri çekilebilir.
- Sürücü birden fazla ifadeye izin veriyorsa `?id=1; DROP TABLE u` → tablo silinir.

**2. Yüksek: Path Traversal deseni** (`'/data/' + req.query.ad`)
Kullanıcıdan gelen değer dosya yoluna kontrolsüz ekleniyor. `?ad=../etc/passwd` gibi `..` içeren istekleri şu an Express'in alt katmanındaki `send` modülü 403 ile reddediyor. Ama güvenliğin tamamı bu örtük davranışa dayanıyor. Ayrıca:
- `/data` altındaki her dosya yetki kontrolü olmadan okunabiliyor.
- `ad` boşsa yol `/data/undefined` oluyor. İçinde null byte varsa istek hataya düşüyor.

**3. Orta: Bilgi sızıntısı**
- `sendFile` hata callback'i almıyor. Hatalar Express'in varsayılan hata işleyicisine gidiyor ve geliştirme modunda stack trace ile sunucudaki gerçek dosya yolu görünüyor.
- `SELECT *` tüm kolonları döndürüyor. Sonuç istemciye gidiyorsa parola hash'i gibi alanlar da sızar.

**4. Bağlama bağlı: Yetkilendirme yok**
İki uç noktada da kimlik doğrulama ya da sahiplik kontrolü görünmüyor. Bu durumda başkasının `id`'si ile kaydı okunabilir (IDOR).

## Düzeltme

```js
app.get('/dosya', (req, res) => {
  res.sendFile(String(req.query.ad), { root: '/data', dotfiles: 'deny' },
    err => err && !res.headersSent && res.sendStatus(404));
});

db.query('SELECT id, ad FROM u WHERE id = $1', [req.query.id]); // mysql: '?'
```

- `root` seçeneği, yolun `/data` dışına çıkmasını resmi ve belgelenmiş şekilde engeller.
- Parametreli sorguda değer SQL koduna karışmaz, her zaman veri olarak gider. `SELECT *` yerine sadece gereken kolonları seçin.
- Kodu çalıştırmadım. Değerlendirme yalnızca okumaya ve `send` modülünün bilinen davranışına dayanıyor.
