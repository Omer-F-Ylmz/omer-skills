Both bugs are fixed and the fixed version passes its checks. The old behavior was reproduced earlier: `ekle(2)` returned `[1, 2]`, and all three buttons printed `2`.

**Root causes**

1. **Mutable default argument.** `liste=[]` is evaluated once, when `def` runs. Every call that omits `liste` appends to that same list, so test runs leak into each other.
2. **Late-binding closure.** `lambda: print(i)` looks up `i` when it is called, not when it is created. After the comprehension ends, `i` is `2`, so all three lambdas print `2`.

**Fix**

```python
def ekle(x, liste=None):
    # None sentinel: a fresh list per call instead of one shared default
    if liste is None:
        liste = []
    liste.append(x)
    return liste

# default arg binds the current i at lambda creation time
dugmeler = [lambda i=i: print(i) for i in range(3)]
```

**Verification:** the fixed file runs `assert ekle(2) == [2]` and checks that the buttons print `0`, `1`, `2`. It printed `ok`. The old code fails the same checks (`[1, 2]` and `2, 2, 2`).
