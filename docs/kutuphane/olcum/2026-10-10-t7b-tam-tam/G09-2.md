# Güvenlik incelemesi (en ağırdan hafife)

**1. Kritik: SQL Injection (CWE-89)**
`req.query.id` doğrudan SQL metnine ekleniyor.
- `?id=1 OR 1=1` tüm kullanıcıları döndürür.
- `?id=0 UNION SELECT ...` başka tabloları okur.
- Sürücü çoklu sorguya izin veriyorsa `?id=1;DROP TABLE u` tabloyu siler.

Sonuç olarak veritabanının tamamı okunabilir ve değiştirilebilir.

**2. Yüksek: Path Traversal / keyfi dosya okuma (CWE-22)**
`'/data/' + ad` için ne izin listesi var ne de kök dizin sınırı.
- `?ad=../etc/passwd` klasik saldırıdır. Express'in kullandığı `send` modülü, `root` verilmemişse `..` içeren yolu şu an 403 ile reddediyor. Yani bu satırı koruyan şey koddaki bir kontrol değil, kütüphanenin bir yan davranışı.
- `/data` içindeki symlink'ler dışarıyı gösterebilir.
- `/data` altındaki her dosya herkese açık.

**3. Orta: Tip doğrulaması yok**
Express'in varsayılan `qs` parser'ı `?id[a]=1` ve `?ad=a&ad=b` gibi girdilerden nesne ya da dizi üretir. Bu düzeltmede de önemli: `mysql` paketi `?` yerine nesne gelirse onu `` `a` = 1 `` ifadesine açar ve bilinen bir auth bypass desenine yol açar. Bu yüzden parametreli sorgu tek başına yetmez, değerin tamsayı olduğu da kontrol edilmeli.

**4. Orta: Yetkilendirme yok (IDOR) ve aşırı veri ifşası**
Kimlik kontrolü olmadığı için herkes her `id`'yi sorgulayabilir. `SELECT *` de parola hash'i gibi alanları döndürebilir.

**5. Düşük: Hata yönetimi yok**
`sendFile` ve `query` hataları ele alınmıyor. Geliştirme modunda Express'in hata sayfası mutlak yolu ve stack trace'i sızdırır.

## Düzeltilmiş hali

```js
app.get('/dosya', (req, res, next) => {
  const ad = req.query.ad;
  if (typeof ad !== 'string' || !/^[\w-][\w.-]*$/.test(ad)) return res.sendStatus(400);
  res.sendFile(ad, { root: '/data', dotfiles: 'deny' }, err => err && next(err));
});

const id = Number(req.query.id);
if (!Number.isSafeInteger(id)) return res.sendStatus(400);
db.query('SELECT id, ad FROM u WHERE id = ?', [id]); // pg kullanıyorsan: $1
```

Yetkilendirme (madde 4) uygulamanın oturum yapısına bağlı olduğu için yukarıdaki koda eklemedim. `/data` dosyaları ve `u` kayıtları kullanıcıya özelse, sorguya oturumdaki kullanıcıyı kontrol eden bir koşul eklenmeli.
