En ağır bulgu SQL injection. İkinci sırada path traversal var.

**1. SQL Injection: Kritik**
`"...WHERE id="+req.query.id` ile kullanıcı girdisi doğrudan sorguya ekleniyor.
- `?id=1 OR 1=1` tüm tabloyu döndürür.
- `?id=0 UNION SELECT ...` başka tablolardan veri çeker.
- Driver birden fazla sorguya izin veriyorsa `?id=1;DROP TABLE u` çalışır.

Çözüm: parametreli sorgu kullanın.

**2. Path Traversal / keyfi dosya okuma: Yüksek**
`'/data/'+req.query.ad` ile yolu istemci belirliyor. Kod hiçbir kontrol yapmıyor. Express'in alttaki `send` modülü `..` içeren yolları kök belirtilmemişken de 403 ile reddettiği için `?ad=../../etc/passwd` güncel Express'te büyük olasılıkla çalışmaz. Bunu çalıştırarak doğrulamadım. Bu kütüphane davranışına güvenmek kırılgan. Ayrıca `/data` içindeki dışarı işaret eden symlink'ler ve `/data` altındaki her dosya yine okunabilir. Çözüm: `root` seçeneği. `send` dosyayı `/data` dışına çıkarmaz.

**3. Yetkilendirme yok (IDOR): Orta (varsayım)**
Snippet'te kimlik doğrulama görünmüyor. Bu doğruysa herkes `/data` altındaki her dosyayı ve `id` değiştirerek her kullanıcı kaydını okuyabilir. Middleware başka bir yerdeyse bu bulgu düşer.

**4. Girdi tipi ve hata yönetimi: Düşük**
- `req.query.*` dizi ya da obje gelebilir. Örneğin `?ad=a&ad=b` sonucu `"/data/a,b"` olur.
- `ad` yoksa yol `/data/undefined` olur.
- `db.query` hatası yakalanmıyor. Promise tabanlı bir driver'da unhandled rejection process'i düşürebilir, bu da DoS demek.

**5. `SELECT *`: Düşük (koşullu)**
Sonuç istemciye dönüyorsa parola hash'i gibi kolonlar sızar.

Düzeltilmiş hali:

```js
app.get('/dosya', (req, res, next) => {
  const ad = req.query.ad;
  if (typeof ad !== 'string' || !ad) return res.sendStatus(400);
  res.sendFile(ad, { root: '/data', dotfiles: 'deny' }, err => err && next(err));
});

if (!/^\d+$/.test(req.query.id)) return res.sendStatus(400);
db.query('SELECT id, ad FROM u WHERE id = ?', [req.query.id]); // pg'de: $1; kolonları ihtiyaca göre seçin
```
