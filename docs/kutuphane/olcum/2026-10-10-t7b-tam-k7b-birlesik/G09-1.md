**1. Kritik: SQL injection** (`db.query("... id="+req.query.id)`)
- Saldırı: `?id=1 OR 1=1` tüm tabloyu döker. `?id=0 UNION SELECT ...` başka tabloları okur. Sürücü çoklu sorguya izin veriyorsa `?id=1; DROP TABLE u` tabloyu siler.
- Düzeltme: parametreli sorgu kullan.
  ```js
  db.query("SELECT * FROM u WHERE id = ?", [req.query.id]);   // mysql
  db.query("SELECT * FROM u WHERE id = $1", [req.query.id]);  // pg
  ```

**2. Kritik/Yüksek: Path traversal** (`'/data/'+req.query.ad` → `sendFile`)
- Saldırı: `?ad=../etc/passwd` ya da `?ad=../app/.env` sunucudaki, işlemin okuyabildiği her dosyayı indirir. Gizli anahtarlar, SSH anahtarları ve kaynak kod da buna dahil.
- Düzeltme: `root` seçeneğini kullan. Express (`send`) `..` ile kök dışına çıkışı 403 ile, null byte'ı 400 ile reddeder. Nokta ile başlayan dosyaları da varsayılan olarak gizler.
  ```js
  app.get('/dosya', (req, res, next) => {
    const ad = req.query.ad;
    if (typeof ad !== 'string' || !ad) return res.sendStatus(400);
    res.sendFile(ad, { root: '/data' }, err => err && next(err));
  });
  ```

**3. Orta: Yetkilendirme yok (IDOR)**
Bu varsayım yalnızca bu satırlara dayanıyor; ayrı bir auth katmanı olabilir. Görünen kodda iki uç nokta da isteyen herkese her dosyayı ve her kullanıcının kaydını veriyor. Erişim, oturumdaki kullanıcıya göre sınırlanmalı.

**4. Düşük: Girdi tipi doğrulanmıyor**
`qs` ayrıştırıcısıyla `?id[]=1&id[]=2` gibi bir istek dizi ya da nesne üretebilir. `id`'yi sayıya çevirip kontrol et (`Number.isInteger`), uymuyorsa 400 dön.

**5. Düşük: `SELECT *` fazla veri döndürüyor**
Şifre hash'i, e-posta gibi kolonlar istemciye sızabilir. Sadece gereken kolonları seç.

**6. Düşük: Hata yönetimi yok**
`sendFile` hatası ve DB hatası işlenmiyor. Geliştirme modunda yığın izi (stack trace) ve dosya yolları istemciye gidebilir.
