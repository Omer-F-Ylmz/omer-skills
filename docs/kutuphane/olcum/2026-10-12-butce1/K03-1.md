Çalışma dizininde hiç `.cs` dosyası yok. Bu yüzden aşağıdaki teşhis ve düzeltme senin koduna değil, tipik bir Orders→Items listelemesine göre yazıldı. Önce `departman-veri-db`, ardından 3. adımdaki `optimizing-ef-core-queries` skill'ini kullandım. Postgres/Supabase kural adımını atladım, çünkü veritabanı belirtilmedi.

## Teşhis

1. Üretilen SQL'i logla ve kaç komut çalıştığını say:
```csharp
optionsBuilder.LogTo(Console.WriteLine, LogLevel.Information);
```
2. N+1'in işareti: önce 1 tane `SELECT ... FROM Orders` çalışır. Ardından her sipariş için bir kez `SELECT ... FROM Items WHERE OrderId = @p` tekrarlanır. N sipariş için toplam N+1 sorgu olur.
3. Bu genelde iki şekilde ortaya çıkar:
```csharp
// a) Lazy loading: virtual Items + Proxies. Döngüde her erişim bir SELECT çalıştırır.
var orders = await db.Orders.ToListAsync();
foreach (var o in orders)
    Console.WriteLine(o.Items.Sum(i => i.Price));

// b) Döngü içinde açık sorgu
foreach (var o in orders)
    o.Items = await db.Items.Where(i => i.OrderId == o.Id).ToListAsync();
```

## Düzeltme

Liste için tercih edilen yol projection. Tek round-trip yeter ve yalnızca gereken kolonlar gelir:
```csharp
var list = await db.Orders
    .AsNoTracking()
    .Select(o => new OrderListItem(
        o.Id,
        o.Items.Count,
        o.Items.Sum(i => i.Price)))
    .ToListAsync();
```

Satırların kendisi gerekiyorsa `Include` kullan:
```csharp
var orders = await db.Orders
    .AsNoTracking()
    .Include(o => o.Items)
    .OrderBy(o => o.Id)
    .ToListAsync();
```

Ek olarak:
- `UseLazyLoadingProxies()` çağrısını kaldır ve navigation'lardaki `virtual` işaretini sil. Böyle bir N+1 sessizce geri gelemez.
- İkinci bir koleksiyon eklersen (ör. `.Include(o => o.Payments)`), satır çoğalmasını önlemek için `.AsSplitQuery()` ekle.
- `Items.OrderId` foreign key olduğu için convention gereği zaten indeksli. Ek bir indeks gerekmiyor.
