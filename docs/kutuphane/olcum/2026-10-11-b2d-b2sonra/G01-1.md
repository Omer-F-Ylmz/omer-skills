**Kök neden: async kodu senkron olarak bekleme (sync-over-async).** Kod, `async` metodun içinde `await` yerine `.Result` kullanıyor:

1. `FirstOrDefaultAsync` sorguyu başlatıyor. Sorgu bitince devam kısmını (continuation) çağıran `SynchronizationContext` üzerinde çalıştırmak istiyor. Bu context klasik ASP.NET'te request context'i, WinForms/WPF'te UI thread'idir.
2. `.Result` bu context'in tek thread'ini sonuç gelene kadar kilitliyor.
3. Devam kısmı, kilitli thread'in boşalmasını bekliyor. Thread de devam kısmının bitmesini bekliyor. Bu karşılıklı bekleme deadlock'a yol açıyor.

Sorgu bazen `.Result`'a gelmeden önce senkron olarak tamamlanıyor, bu yüzden hata "zaman zaman" görülüyor. ASP.NET Core'da `SynchronizationContext` olmadığı için klasik deadlock oluşmaz. Ama aynı kod yük altında thread-pool'u tüketir (thread-pool starvation) ve istek yine takılır.

**Düzeltilmiş hâli:**

```csharp
public async Task<Order?> Get(int id)
{
    return await _db.Orders.FirstOrDefaultAsync(x => x.Id == id);
}
```

Daha kısa bir alternatif de var: `public Task<Order?> Get(int id) => _db.Orders.FirstOrDefaultAsync(x => x.Id == id);`

**Önemli:** `Get`'i çağıran kodlar da `await` kullanmalı. Çağrı zincirinin bir yerinde `Get(id).Result` veya `.Wait()` kalırsa deadlock aynen devam eder. Async kullanımı en üst seviyeye kadar sürdürülmeli ("async all the way"). `ConfigureAwait(false)` yalnızca kütüphane kodunda ek bir önlem olarak eklenebilir. Asıl düzeltme `.Result`'ı kaldırmak.
