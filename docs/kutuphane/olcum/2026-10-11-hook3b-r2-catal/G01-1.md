**Kök neden:** `async` metodun içinde `await` yerine `.Result` ile beklemek, yani async işi senkron olarak bloklamak.

- `FirstOrDefaultAsync` bir `Task` döndürür ve DB cevabı gelince devamı yakalanan `SynchronizationContext` üzerinde çalışmak ister. Bu bağlam klasik ASP.NET, WinForms, WPF ya da Blazor Server'da vardır.
- `.Result` aynı thread'i/bağlamı bloklar. Task o bağlama dönemediği için tamamlanamaz, `.Result` da task bitmeden geri dönmez. Sonuç deadlock.
- **"Zaman zaman" olmasının nedeni:** Task senkron tamamlanırsa (ör. sonuç hazırsa) `.Result` hemen döner ve sorun çıkmaz. Gerçekten asenkron giderse kilitlenir. ASP.NET Core'da `SynchronizationContext` yoktur, orada belirti klasik deadlock değil, yük altında thread pool'un tükenmesi ve isteklerin askıda kalmasıdır.
- Ek olarak metot `async` olduğu hâlde içinde `await` yok. Derleyici bunu CS1998 uyarısıyla bildirir.

**Düzeltilmiş hâli:**

```csharp
public async Task<Order?> Get(int id)
{
    return await _db.Orders.FirstOrDefaultAsync(x => x.Id == id);
}
```

Arada başka iş yoksa daha kısa yazılabilir:

```csharp
public Task<Order?> Get(int id) => _db.Orders.FirstOrDefaultAsync(x => x.Id == id);
```

**Dikkat:** Bu metodu çağıran yerler de `await` kullanmalı. Zincirin herhangi bir yerinde `.Result`, `.Wait()` veya `GetAwaiter().GetResult()` kalırsa deadlock riski sürer, bu yüzden çağıranlarda da bu üçünü arayın.
