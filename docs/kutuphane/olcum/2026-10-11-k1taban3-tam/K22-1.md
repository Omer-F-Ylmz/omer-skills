Adımlar aşağıda. Hiçbir şey çalıştırmadım; yalnızca skill dosyalarını okudum. İki şeyi bilmen gerek. Kurulu `/ship` skill'i CHANGELOG yazıyor ama **git tag oluşturmuyor**; bu skill'in hiçbir dosyasında `git tag` geçmiyor. Ayrıca şu anki klasör (`olcum-ogikgdgv`) bir git deposu değil, bu yüzden bu adımlar senin gerçek proje deponda koşmalı.

**Okuma sırası:** önce `departman-surec-git-yayin`, sonra adım 4'teki `ship`. Skill önce sürüm numarasını belirliyor (adım 12), sonra CHANGELOG'u yazıyor (adım 13); aşağıdaki sıra bunu izliyor.

1. **Dal:** Skill `main`'de ya da ana dalda koşmayı reddeder. Önce bir özellik dalına geç.
2. **Hazırlık kontrolü:** `git status`, `git diff <base>...HEAD --stat` ve `git log <base>..HEAD --oneline` ile neyin çıkacağını gör. Ardından ana dalı `git fetch origin <base> && git merge origin/<base>` ile içeri al.
3. **Test, kapsam ve inceleme (adım 4-11):** Testler kırmızıysa süreç durur. Bu adımlarda skill kendi ön incelemesini de yapar.
4. **Sürüm numarası (adım 12):** `gstack-version-bump classify --base <base>` mevcut durumu okur. 50 satırdan küçük değişiklik MICRO, daha büyüğü PATCH olur; bunları skill kendisi seçer. MINOR ya da MAJOR gerekiyorsa sana sorar. Sürüm `gstack-version-bump write --version X.Y.Z.W` ile yazılır. Biçim 4 haneli: `MAJOR.MINOR.PATCH.MICRO`.
5. **CHANGELOG (adım 13):**
   - Commit listesini `git log <base>..HEAD --oneline` ile, tam diff'i `git diff <base>...HEAD` ile çıkar.
   - Commit'leri temalara ayır ve başlığı `## [X.Y.Z.W] - 2026-10-11` olan bir kayıt yaz. Bölümler: `### Added / Changed / Fixed / Removed`.
   - Kayıt dosya başlığından sonra eklenir. Her commit en az bir maddeye karşılık gelmeli.
6. **Commit (adım 15):** VERSION ve CHANGELOG en son commit'e girer: `chore: bump version and changelog (vX.Y.Z.W)`. Commit'in sonuna `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>` satırı eklenir.
7. **Doğrulama ve push (adım 16-17):** Testlerin güncel kanıtı olmadan push yapılmaz. Push'tan önce sır taraması temiz olmalı (`departman-guvenlik` adım 1). Push `git push -u origin <dal>` ile yapılır; force push kullanılmaz.
8. **PR (adım 18-19):** Önce `/document-release` dokümanları günceller. Sonra PR başlığı `v<X.Y.Z.W> <tür>: <özet>` biçiminde açılır.
9. **Tag:** Skill bunu kapsamıyor, PR merge edildikten sonra elle yapılmalı:
   ```
   git checkout main && git pull
   git tag -a vX.Y.Z.W -m "vX.Y.Z.W"
   git push origin vX.Y.Z.W
   ```
10. **Kapanış:** `finishing-a-development-branch` ile dalı kapat. Rapor en fazla 15 satır olur: commit, test sayısı, CI, sapmalar.

Push, PR ve tag push dışarıya yayın yapan adımlar. "Çalıştır" dersen başlarım; o noktalarda yine onayını alırım.
