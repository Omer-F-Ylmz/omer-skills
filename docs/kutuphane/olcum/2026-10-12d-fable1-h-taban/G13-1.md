Two separate root causes, both reproduced.

**1. Mutable default argument (`liste=[]`)**
The default list is created once, when the function is defined, and every call without a `liste` argument reuses it. Reproduced: `ekle(1)` → `[1]`, then `ekle(2)` → `[1, 2]`. This is why tests running in one process leak state into each other.

**2. Late-binding closure (`lambda: print(i)` in a comprehension)**
The lambda captures the variable `i`, not its value. By the time the buttons run, the loop has finished with `i == 2`. Reproduced: all three buttons print `2`.

**Fix**

```python
def ekle(x, liste=None):
    if liste is None:
        liste = []
    liste.append(x)
    return liste

dugmeler = [lambda i=i: print(i) for i in range(3)]
```

Verified with `python -I`: asserts pass, `ekle(1)` → `[1]`, `ekle(2)` → `[2]`, and the buttons print `0`, `1`, `2`.

Skipped: a `functools.partial` or factory function for the buttons. The default-argument capture is the smallest correct change. Scratch files are in `/tmp` (`repro.py`, `fixed.py`); the original snippet was inline, so I didn't edit a project file.
