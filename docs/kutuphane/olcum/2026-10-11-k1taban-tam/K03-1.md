Çalışma dizini boş, yani düzeltilecek gerçek bir kod yok. Aşağıdaki teşhis ve düzeltme tipik bir Orders→Items listelemesine göre yazıldı; dosyaya uygulanmadı, test edilmedi.

**İzlenen sıra:** önce `departman-veri-db`, sonra onun 3. adımı olan `dotnet-data:optimizing-ef-core-queries`. `supabase-postgres-best-practices` çalıştırılmadı çünkü veritabanı sağlayıcısı belli değil. `departman-test-qa` da çalıştırılmadı çünkü test edilecek proje yok.

## Teşhis

Önce üretilen SQL'i görün:
```csharp
optionsBuilder.LogTo(Console.WriteLine, LogLevel.Information);
var orders = await db.Orders.TagWith("OrderList").ToListAsync();
```
N+1 olduğunu şu gösterir: logda 1 adet `SELECT ... FROM Orders` ve ardından sipariş başına bir `SELECT ... FROM Items WHERE OrderId = @p` görünür. Sipariş sayısı N ise toplam N+1 sorgu çıkar.

Bu genelde şu üç sebepten birinden kaynaklanır:
1. Lazy loading açıktır (`UseLazyLoadingProxies` ile `virtual ICollection<Item> Items`) ve döngüde `o.Items` okunur.
2. Döngü içinde `db.Items.Where(i => i.OrderId == o.Id)` sorgusu çalıştırılır.
3. Döngü içinde `db.Entry(o).Collection(x => x.Items).Load()` çağrılır.

## Düzeltme

Listeleme için en iyi yol projeksiyon. Tek bir round-trip yapar, tracking olmaz ve yalnız gereken kolonlar gelir:
```csharp
var list = await db.Orders
    .OrderBy(o => o.Id)
    .Where(o => o.Id > lastSeenId)          // keyset sayfalama
    .Take(pageSize)
    .Select(o => new OrderDto(
        o.Id, o.CreatedAt,
        o.Items.Select(i => new ItemDto(i.Id, i.ProductName, i.Quantity, i.Price)).ToList()))
    .ToListAsync();
```
Entity olarak dönmeniz gerekiyorsa: `db.Orders.Include(o => o.Items).AsNoTracking()`. İkinci bir collection `Include` eklerseniz Kartezyen patlamayı önlemek için `.AsSplitQuery()` ekleyin.

Lazy loading'i kaynağında kapatın: `UseLazyLoadingProxies()` çağrısını silin ve `virtual` niteleyicisini kaldırın. Böyle yapmazsanız başka bir ekran aynı N+1'i yeniden üretir.

`Items.OrderId` foreign key olduğu için index'i konvansiyonla zaten oluşur, ek index gerekmez.

## Doğrulama

Bu test sorgu sayısının sipariş sayısından bağımsız kaldığını kontrol eder:
```csharp
class CountingInterceptor : DbCommandInterceptor {
    public int Count;
    public override ValueTask<InterceptionResult<DbDataReader>> ReaderExecutingAsync(
        DbCommand c, CommandEventData e, InterceptionResult<DbDataReader> r, CancellationToken ct = default)
    { Count++; return base.ReaderExecutingAsync(c, e, r, ct); }
}
// Test: 50 order × 3 item seed → listeyi çağır → Assert.Equal(1, interceptor.Count);
```
Düzeltmeden önce bu test kırmızı vermeli (51 sorgu), düzeltmeden sonra yeşile dönmeli (1 sorgu; split query kullanırsanız 2).

Bunu gerçek koda uygulamam için `DbContext`'in ve listeleme metodunun yolunu verin.
