**Varsayım:** PostgreSQL 12 veya üstü. Mesaj veritabanını belirtmiyor ve klasörde repo yok, bu yüzden plan genel; tablo ve kolon adları örnek. MySQL veya SQL Server ise söyle, adımlar değişir.

Kullandığım skill'ler: `departman-veri-db` → `supabase-postgres-best-practices` (kurallar) → `ecc:database-migrations` (expand-contract deseni).

## 0. Önce şunu sor: sabit bir varsayılan değer yeterli mi?
Her satıra aynı değer yazılabiliyorsa tek adım yeter. PG11+ sürümlerde bu sadece katalog güncellemesidir; tablo yeniden yazılmaz, kilit anlıktır:
```sql
SET lock_timeout = '3s';
ALTER TABLE orders ADD COLUMN region text NOT NULL DEFAULT 'TR';
-- geri al: ALTER TABLE orders DROP COLUMN region;
```
Değer satıra göre hesaplanacaksa aşağıdaki 6 adımı uygula.

## 1. Kolonu NULL kabul eder halde ekle
```sql
SET lock_timeout = '3s';   -- kilidi alamazsa hemen vazgeçer, kuyruk birikip tablo kilitlenmez
ALTER TABLE orders ADD COLUMN region text;
-- geri al: ALTER TABLE orders DROP COLUMN region;
```

## 2. Uygulamayı deploy et: yeni satırlarda bu kolon her zaman dolu yazılsın
Bu adım 5'ten önce şart. Yoksa adım 5'ten sonra kolonu yazmayan eski kodun INSERT'leri hata verir.

## 3. Eski satırları partiler halinde doldur (DDL'den ayrı migration)
```sql
UPDATE orders SET region = <hesap>
WHERE id IN (SELECT id FROM orders WHERE region IS NULL LIMIT 5000);
-- 0 satır kalana kadar tekrarla; her parti ayrı transaction
```
Migration araçları çoğu zaman her şeyi tek transaction'a sarar. Bu yüzden döngüyü script ya da job olarak koş.

## 4. Kontrolü tabloyu kilitlemeden doğrula
```sql
ALTER TABLE orders ADD CONSTRAINT orders_region_nn CHECK (region IS NOT NULL) NOT VALID;  -- anlık
ALTER TABLE orders VALIDATE CONSTRAINT orders_region_nn;  -- okuma ve yazma devam eder
```

## 5. NOT NULL'a çevir ve geçici kontrolü kaldır
```sql
SET lock_timeout = '3s';
ALTER TABLE orders ALTER COLUMN region SET NOT NULL;  -- PG12+ geçerli CHECK'i kullanır, tabloyu taramaz
ALTER TABLE orders DROP CONSTRAINT orders_region_nn;
-- geri al: ALTER TABLE orders ALTER COLUMN region DROP NOT NULL;
```

## 6. Test ve onay
- Önce yerelde, üretime yakın boyutta veriyle dene. Adım 5'in anlık bittiğini görmek için `pg_locks` ile kilit süresine bak.
- Üretimdeki migration yalnız senin onayınla çalışır (departman kapısı).

`ecc:database-migrations` skill'inde bir hata var: "NOT NULL default'suz eklenirse tablo yeniden yazılır" diyor. Gerçekte dolu bir tabloda bu komut hata verip durur. Asıl tehlike, `SET NOT NULL` komutunun doğrudan çalıştırıldığında tabloyu tamamen taraması ve bu sürede yazmaları kilitlemesi. Adım 4 bu yüzden var. `supabase` skill'ini Supabase projesi belirtilmediği için, RLS adımını da yeni kolon yetkiyi etkilemediği için atladım.
